# 3. Infrastructure as Code ja Terraform ## Oppimistavoitteet - ymmärtää Infrastructure as Code -periaatteen - ymmärtää Terraformin toimintamallin - tulkita Terraform Plan -tuloksia --- # Infrastructure as Code Infrastructure as Code (IaC) tarkoittaa, että infrastruktuuri kuvataan ohjelmakoodina. Esimerkiksi: - virtuaalikoneet - tietokannat - verkot - Kubernetes-klusterit voidaan määritellä tiedostoissa. --- # Miksi Infrastructure as Code? Manuaalisessa hallinnassa: - dokumentointi vanhenee - virheet lisääntyvät - ympäristöjen erot kasvavat IaC mahdollistaa: - versionhallinnan - auditoinnin - automaation - toistettavuuden --- # Terraform Terraform on Infrastructure as Code -työkalu. Terraform käyttää deklaratiivista mallia. Kehittäjä määrittelee: "Miltä ympäristön tulee näyttää" eikä "Miten ympäristö rakennetaan vaiheittain" --- # Terraform Workflow init ↓ validate ↓ plan ↓ apply ↓ destroy --- # State Terraform ylläpitää state-tiedostoa. State sisältää tiedon: - olemassa olevista resursseista - resurssien tunnisteista - riippuvuuksista State mahdollistaa muutosten laskemisen. --- # Terraform Plan Plan näyttää: - mitä luodaan - mitä muutetaan - mitä poistetaan Plan toimii käyttöönoton tarkastusraporttina. --- # Terraform CI/CD:ssa Terraform sopii erityisen hyvin GitHub Actions -putkiin, koska infrastruktuurimuutokset voidaan validoida ennen käyttöönottoa. Yleinen malli: Pull Request → Validate → Plan Main Branch → Apply
